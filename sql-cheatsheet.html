Class 5 Reference

Beginning SQLite Cheat Sheet

Turn the zoo CSV into a table. Start with CREATE, INSERT, and SELECT with WHERE; try UPDATE and DELETE as extensions.

Class 5 notes

Commands at a glance

CREATE TABLE
Define a new table: name its columns, choose types, and add rules such as a primary key.
INSERT INTO … VALUES
Add rows. INTO names the table and columns; VALUES supplies the matching data.
SELECT … FROM
Read data. SELECT chooses columns (* means all); FROM names the table.
WHERE
Choose rows that match a condition. This clause accompanies SELECT, UPDATE, or DELETE; it is not a standalone command. Use = to compare values.
UPDATE … SET
Modify existing rows. SET names the columns and their new values; WHERE limits which rows change.
DELETE FROM
Remove rows from a table. Add WHERE to limit which rows are removed; the table itself remains.

Basics: End statements with ;, put text in single quotes, and begin a comment with --. INTEGER is used for whole numbers and TEXT for text. PRIMARY KEY identifies a row; NOT NULL disallows a null value.

Before changing data: Preview the target rows with SELECT and the same WHERE condition. Omitting WHERE from an update or delete affects every row.

Worked examples: the animals table

Run these SQL statements in your SQLite tool's SQL editor with your zoo database open. Start with a new database for this walkthrough. Creating the table does not import the CSV: each CSV data row must become an inserted record.

1. CREATE TABLE — define the columns

CREATE TABLE animals (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    species TEXT,
    habitat TEXT,
    image TEXT
);

The four CSV headers become columns; add id to identify each animal. TEXT stores text, and NOT NULL requires a non-null value. In this table, SQLite assigns an integer ID when you omit it from an insert. Run this step once; creating the same table again raises an error.

2. INSERT INTO — add records

INSERT INTO animals (name, species, habitat, image)
VALUES
    ('Polar Bear', 'Bear', 'Arctic', 'bear.png'),
    ('Elephant', 'Elephant', 'Savannah', 'elephant.png'),
    ('Otter', 'Otter', 'Rivers', 'otter.png');

Match each value to the column list in order. Use single quotes around text and a semicolon to end the statement. The image column stores a filename; the image file stays in the app's static images folder. Add the remaining CSV rows using the same pattern. Repeating an insert adds more rows.

3. SELECT — read records

SELECT * FROM animals;

SELECT name, habitat
FROM animals;

* means all columns. Listing column names chooses which fields appear in the result. Neither query changes the stored data.

4. WHERE — filter records

SELECT name, habitat
FROM animals
WHERE habitat = 'Arctic';

This returns Polar Bear and Arctic from the sample records. Think of Python's if animal["habitat"] == "Arctic":: SQL uses = for this comparison. The WHERE clause chooses rows; the column list after SELECT chooses fields.

5. UPDATE — modify a record (extension)

-- Inspect the target record first.
SELECT * FROM animals WHERE id = 1;

UPDATE animals
SET name = 'Snowball'
WHERE id = 1;

SELECT * FROM animals WHERE id = 1;

In this fresh example, ID 1 is the polar bear. In your own database, look up the ID first. UPDATE changes values in existing rows; it does not change the table's columns. Without WHERE, every row is updated.

6. DELETE — remove a record (extension)

-- Inspect the target record first.
SELECT * FROM animals WHERE id = 3;

DELETE FROM animals
WHERE id = 3;

SELECT * FROM animals WHERE id = 3;

This removes the sample otter record; the final query returns no rows. The table still exists. Without WHERE, every row is deleted. Practice on your sample data and check the ID before running the command.

Practice: Insert the rest of your CSV animals, filter by a different habitat, and compare the result with your Python output. Then adapt the records to your group's zoo theme. If your SQLite tool has a Save or Commit action for pending changes, use it before checking the webpage.
